# mydraw — notes for agents

Roadmap and phase status: `plan.md`. Read it before starting a phase.

## Architecture
- `app/src/boot.ts` (`app/dist/boot.cjs`, package.json `main`): requires `cli.cjs` when `MYDRAW_CLI_ARGS` is set, else `main.cjs` (a packaged app can only start through its own entry). See "Packaging".
- `app/src/main.ts`: Electron main. Serves `web/dist` over the privileged `app://mydraw` scheme (prod) or loads `MYDRAW_DEV_URL` (dev). All file I/O, dialogs, menus, settings and the crash-recovery folder live here. The renderer may only write to paths the user opened or picked (`allowedPaths`).
- `app/src/cli.ts`: the headless `mydraw` CLI main process (see Export part 2). `app/src/pdf.ts`: PDF printing for both.
- `app/src/preload.ts`: exposes `window.mydraw` (typed by `MydrawBridge` in `shared/types.ts`). Context isolation + sandbox on; add new IPC here and in `shared/types.ts` together.
- `web/src/App.tsx`: tabs, save/autosave, recovery, file-watch conflicts, close flow. One mounted `<Excalidraw>` per tab (hidden when inactive) so each keeps its own undo history. Latest state is read through refs (`tabsRef`, `settingsRef`, `apis`) because callbacks come from Excalidraw, IPC and timers.
- Dirty tracking: `sceneHash` (element versions + count + background) compared with a per-tab baseline set on first `onChange` after load, after save, and after reload.
- Drawing style (Clean/Sketch) sets `currentItem*` app state only; it never edits existing elements. Shown and switched by the tab bar's `.md-style-switch [data-drawing-style]` (`TabBar` props `drawingStyle` / `onDrawingStyle`), besides the menus and palette.

## Stencil library
- `app/src/library.ts` (`LibraryStore`): scans the library folder (collections = top-level folders; items = .svg/.png, `.stencil.json`, entries of `.excalidrawlib`), watches it, keeps favorites/recent in `library.json`. Item ids are root-relative paths (`#n` for .excalidrawlib entries). Files are served to the renderer via the `mdlib://library/<path>` protocol, confined to the root.
- `app/src/packs.ts`: icon-pack downloader (plain Node; also `scripts/fetch-packs.mjs`). Iconify sets (carbon, logos, mdi, tabler, lucide, devicon, simple-icons) come from `@iconify-json/<name>` on npm; Dashboard Icons from the GitHub tree (12 parallel downloads, dark/light duplicates and files over 100 KB skipped). `uninstallPack` deletes a pack folder only when its `collection.json` has `managedBy: "mydraw-packs"` and the matching pack id. The packs dialog (`PacksDialog` in `web/src/library/dialogs.tsx`, opened by the **Icon packs…** button beside the panel title) has nothing ticked by default, keyword search + sort (`shared/packList.ts`) and an inline two-step Remove per installed pack. The "Add name under icons" checkbox sits on the panel itself. `shared/iconSelect.ts` (pure, tested) picks infrastructure icons from the big generic sets and holds `MONO_ICON_COLOR`: one-color sets get that color baked in, because near-black vanishes on the dark canvas. Packs build in `.<Collection>.installing` and replace only folders whose `collection.json` has `managedBy: "mydraw-packs"`.
- `web/src/library/stencilContent.ts`: item → elements (+ image files, fileId = SHA-1 of the bytes), `cloneForInsert` (fresh ids, remapped bindings/groups), `insertStencil`. Reuse these for MCP `place_stencil` in Phase 2.
- Stencils is the only library UI. Excalidraw's own Library button and its "Add to library" menu item are hidden by CSS in `web/src/styles.css` (no `onLibraryChange`, no `initialData.libraryItems`, no sync). `.excalidrawlib` files are an import format for the Stencils panel (each becomes a collection whose entries are `xlib` items; rename/delete edit the file); the Export dialog can also WRITE one (see "Portable drawings and follow-ups"). "Quick Save as Stencil" (⌥⌘S, `quickSaveStencil` command) saves the selection to My Stencils without a dialog. `LibraryStore.saveStencil` refuses managed packs and pack-only collections.
- Panel → canvas drag uses the `application/x-mydraw-stencil` type and is handled in a capture-phase drop listener in `App.tsx`, before Excalidraw sees it.
- Icon recolor: `shared/recolor.ts` (`recolorSvg`, pure + unit-tested) rewrites fills/strokes/stops/currentColor, keeping near-white and transparent parts. `web/src/library/iconColor.ts` swaps the element's `fileId` to the recolored SVG and keeps the original SVG in `customData.mydrawOriginalSvg` (+ `mydrawIconColor`), so recolors never compound and "Original" restores. Reuse for an MCP `recolor` tool.
- **Hand-drawn icons** (`shared/iconSketch.ts` model, presets, settings, no roughjs; `shared/sketchSvg.ts` pure drawing, `tests/sketchSvg.test.ts`; `web/src/library/sketchIcon.ts` DOM walk; `web/src/library/iconPreview.ts` previews): a sketch is another rendering of the icon like a recolor: `restyledIcon(el, file, {color?, sketch?})` in `iconColor.ts` always renders original → `recolorSvg` → sketch, keeps `mydrawOriginalSvg` (PNG: `mydrawOriginalImage`) and `customData.mydrawIconSketch` = `IconSketch` {roughness, fill solid|hachure|cross-hatch|zigzag|dashed|none, seed, mode rough|wobble, outline shade|ink|same|none, weight, offset, hatchGap, hatchAngle, doubleStroke, texture none|pencil|paper, preset?}; missing fields default (old files stay valid), `preset` is only a tag kept while the look equals that preset. Presets `ICON_STYLE_PRESETS`: pen (alias hand-drawn), marker, pencil, crayon, ink, line-art, hatch, wobble. roughjs `dots` (huge output) and `zigzag-line` (draws nothing at icon size) are deliberately not offered. `rough`: the SVG is mounted in a hidden shadow root (its `<style>` can't leak; do NOT use `visibility:hidden` on the host, it is inherited and every shape reads as hidden), each visible shape's computed fill/stroke + screen CTM scale go to `sketchShape` (roughjs in px space: path scaled by `scale`, wrapped back in `scale(1/s)`; solid fill barely jittered, outline carries the look; patterned fills only for shapes ≥ 14 px; `offset` translates fill paths (role "fill"); ink turns only dark strokes (max channel < 100) black). Textures = `grainFilter` (feTurbulence alpha mask, userSpaceOnUse) in the root `<defs>`, on the whole shape (pencil) or its fills (paper). `wobble` (PNG, and SVGs with `<image>` or > 400 shapes): `feTurbulence` + `feDisplacementMap` wrapper. Seed 1 for inserts (same icon = same file), Redraw = new seed. Caches key on `sketchKey`. `restyleIcons(api, patch|fn, preview, ids)` + `IconRecolorSession.applyPatch` = one undo step. Insert default: `Settings.iconStyle` auto|original|hand-drawn + `Settings.iconSketch` (a full look, `lookOfSetting`), resolved by `insertSketchOf` (auto = hand-drawn in Sketch) and passed as `LabelOptions.sketch` to `loadStencil` (`sketchContent`: images restyled, Excalidraw shapes of .stencil/.excalidrawlib get roughness 1); AgentHost `insertSketch()`, QuickConnect `insertSketch`. UI: Stencils panel `InsertStyle` (`.md-ins-btn` beside the search box, its thumbnail = a sample icon as a click inserts it; popover `.md-ins-pop`: `.md-ins-preview`, look tiles `[data-look=original|pen|…]` (a look tile keeps Auto, Original sets original), `input[data-icon-style=auto]` = Follow drawing style (off = always hand-drawn); tile previews in the list follow the insert look), style panel `web/src/IconStyleSection.tsx` (`.md-iconstyle[data-mode]`, row `[data-icon-style=original|pen|pencil]` with real previews, window `.md-more-pop[data-more-pop=iconStyle]`: `[data-style-tile]`, `[data-fill]`, `[data-outline]`, `.md-is-range[data-field]`, `[data-texture]`, `[data-double]`, `.md-iconstyle-redraw`; nothing selected = insert look + Auto/Original/Drawn), palette "Icons: <look> look". Agent: `iconStyle` on place_stencil / update_elements / build_diagram nodes (look sketch → pen icons and drawn shapes); get_scene `icon.style` / `iconStyle`. Test hooks `imageSketches()`, `imagePresets()`, `imageWeights()`.
- **Caption fonts** (names under icons): `Settings.captionFont` match|hand|drawing (default match) + `captionHandFont` (default Excalifont); pure rule `captionFontName` in `shared/iconSketch.ts`; renderer `web/src/library/captionFont.ts` (`captionFontId` for inserts: App `labelOptions`, AgentHost `captionFont`, QuickConnect `captionPrefs`; `captionsOf` = icon node bound text or the single free text grouped with a panel stencil image; `restyleCaptions` re-fits via `styleElements` and keeps free captions centred, EVENTUALLY so it joins the icon restyle's undo step (`IconRecolorSession.applyPatch(..., after)`), IMMEDIATELY when used alone; `captionStateOf` for the UI; `handFonts`, `fontCss`). Excalidraw adds its own fonts to the page only when a drawing uses them, so menu previews use `md-preview-Excalifont/Virgil` `@font-face` rules at the top of styles.css (pinned file name, listed in EXCALIDRAW-UPGRADE.md). UI: panel popover `.md-panel-names [data-names=off|match|hand|drawing]` (Off = no captions, the old Names toggle), `.md-ins-fontbtn` → `.md-font-menu [data-hand-font]`; window `.md-is-names[data-caption-state] [data-caption]`, `.md-is-font`. Test hook `captionFonts()`.
- Excalidraw 0.18 records selection changes in undo history.
- Dark mode: Excalidraw inverts its canvases with a CSS filter and pre-corrects images (approximately: saturated colours shift), but not files whose mimeType is exactly `image/svg+xml`. SVG icon files use `image/svg+xml;mydraw=truecolor` (`web/src/library/trueColor.ts`, applied on insert, recolor and file open) so they count as images. On screen the static canvas is themed in-canvas instead (see "Static canvas hook" below), which makes images exact; dark exports are exact through Excalidraw's export path. Detect SVGs by data URL, not mimeType.
- SVG files must have numeric width/height (`ensureSvgSize`), otherwise Excalidraw's raster-image export crops them.
- Eyedropper (`web/src/library/pickColor.ts`): `elementAt` hit-tests scene coords (topmost; bound text → container, except with `{labels: true}`, which the eyedropper passes so a label gives its OWN color; unfilled shapes only near their outline, counting both halves of a thick stroke: half the stroke width + pointer slack either side of the edge; arrows/lines/freehand last, tolerance = half the stroke width + slack; text gets the same pointer slack, scaled by zoom) and `colorOfElement` reads the real color (`customData.mydrawIconColor`, `dominantSvgColor`, raster quantisation, or fill/stroke). Pick mode swallows the canvas click in a capture-phase listener so the selection is kept.
- Icon color lives in the Colors tab of `StyleSection` as the **Icon** target (shown when SVG icons are selected; the only target when only icons are selected). It reuses the palette, shades, last-custom swatch, eyedropper and `ColorPicker` (live preview via `onIconColor(color, true)`), plus an **Original colors** chip. There is no separate icon color section any more.
- Live recolor previews use `CaptureUpdateAction.NEVER`; `IconRecolorSession` restores the pre-drag elements (NEVER) before the final IMMEDIATELY change, so a drag is one undo step. Don't use EVENTUALLY here: in 0.18 it merges into the *previous* committed change.
- When swapping an image's `fileId`, call `updateScene` first and `addFiles` after; Excalidraw only starts loading images for files added while an element references them (otherwise a grey placeholder shows until some later update).
- Excalidraw handles keyboard shortcuts only when its canvas has focus (tests click the canvas first).
- Console "font-src" CSP errors for `esm.sh` are expected: Excalidraw lists a CDN fallback after our local fonts; CSP blocks it so the app stays offline.

## Agent control (MCP, Phase 2)
- Path: Claude Code → `mcp/src/index.ts` (stdio MCP server, bundled to `mcp/dist/index.js` by `scripts/build-mcp.mjs`) → HTTP `POST 127.0.0.1:<port>/rpc` → `app/src/control.ts` → `app/src/agent.ts` (main) → IPC `agent:command` → `web/src/agent/executor.ts` (renderer) → reply on `agent:reply`.
- `control.ts`: loopback only, random port, 32-byte key as `Authorization: Bearer`. Refuses any request with an `Origin` header or a non-loopback `Host` (CSRF / DNS rebinding). `{port, key, pid}` in `<userData>/control.json`, chmod 600, removed on quit.
- `agent.ts` runs library and file-system methods in main (`search_stencils`, `add_stencil_file`, `delete_stencil`, `open_drawing`, writing exports, allowing `save` paths) and forwards the rest. `place_stencil` gets the full `LibraryItem` from main, so freshly added stencils work before the renderer's index refreshes.
- Executor: commands run strictly one at a time against the latest scene; every scene change is a single `updateScene(IMMEDIATELY)` that merges by element id, so one MCP call = one undo step and user edits made meanwhile are kept. Selection changes from `select` use `NEVER`.
- `web/src/agent/sceneOps.ts`: `buildElements` (skeletons via `convertToExcalidrawElements` with `regenerateIds: false`; arrows with `from`/`to` are drawn edge to edge with `shared/geometry.ts` and bound by hand, because the converter only binds within its own batch), `applyUpdates` (moves/resizes re-centre labels via `relabel` and `reroute` bound arrows), `deleteElements` (unbinds arrows), `describe` (compact `get_scene` output; bound labels folded into their container).
- **Stale code**: the app reads its web UI and main process once at startup, and the MCP server its own file, so after `npm run build` a running instance keeps the OLD code (fixes seem not to work, new tools are missing). `shared/buildId.ts` (`buildId(root)`: hash of `web/dist/index.html`, `app/dist/main.cjs`, `preload.cjs`) is written into `control.json` (`build`, `appPath`) at startup; the MCP server (`staleNotes` in `mcp/src/index.ts`) compares it with disk (only when `appPath` is this checkout) and also notices its own rebuilt file, and adds a `WARNING:` text block to a tool result (once per problem, always on `list_drawings`). Restart the app after a build before judging a fix.
- **Arrow-label safety net**: `commit()` in `web/src/agent/executor.ts` calls `detachedLabels` (`shared/labelGuard.ts`, pure, `tests/labelGuard.test.ts`) for the arrows a change touched: a bound label farther than 60 px from its arrow is moved back to `labelPoint` (also defined there), whatever put it there. Smoke builds labelled zone-to-zone arrows, checks every label sits on its arrow, displaces one and checks the next change fixes it.
- Undo/redo click the tab's own `[data-testid="button-undo"]` (each `DrawingView` root has `data-md-tab`); Excalidraw's API has no undo call.
- Drawings are addressed by `drawing` = tab id, file path or title; default active tab.
- MCP finds the app via `MYDRAW_USER_DATA` (default `~/Library/Application Support/mydraw`). If it isn't running: the copy shipped in an app (`<x>.app/Contents/Resources/mcp/index.js`, `ownBundle`) launches THAT app; the checkout's copy launches `MYDRAW_APP` if set, else the checkout's dev build with the branded Electron (`npm run build` first), never an installed app. `staleNotes` also warns when the connected app is not the expected one (bundle mismatch, or the checkout connected to an installed app). `MYDRAW_NO_LAUNCH=1` disables launching (smoke test).
- Register: installed app = the Set up window's **Connect Claude Code** (= `claude mcp add --scope user mydraw -- /Applications/mydraw.app/Contents/Resources/bin/mydraw mcp`); checkout `claude mcp add --scope user mydraw -- node ~/Projects/mydraw/mcp/dist/index.js` (`~/Projects/mydraw` and `~/Documents/projects/mydraw` are the same folder). Check with `claude mcp list`. MCP server version = app version (`APP_VERSION`).
- **Keeping the MCP up to date**: tool list and schemas live only in `mcp/src/index.ts` (59 tools, 2 prompts `tidy_diagram`, `polish_diagram`; `get_conventions` is answered by the MCP server itself, from `shared/conventions.ts`); handlers are `case`s in `web/src/agent/executor.ts` (renderer) and `app/src/agent.ts` (main). A new agent parameter needs the zod schema + description there, the MCP `instructions` when it is a new capability, and a bump of `VERSION`. Internal methods without a tool: `open_files`, `ping`, `render_export`, `stencil_content`.

## Ask Claude box (Phase 10)
- **Entry points**: tab-bar button `.md-ask-btn` (`TabBar` props `askOpen` / `askBusy` (`.busy` + `.md-ask-btn-dot`) / `onAsk`), ⌥⌘J, Diagram menu, palette. The box hangs under the button (`.md-ask-drop`, placed from the button's rect in a layout effect, re-placed on resize; bottom centre when the button is missing).
- **Flow**: `web/src/AskClaude.tsx` (box `.md-ask[data-ask-state=idle|starting|running|done|failed|cancelled]`, `.md-ask-input`, `.md-ask-send`, `.md-ask-tidy`, `.md-ask-polish`, `.md-ask-cancel`, `.md-ask-model`, `.md-ask-steps`, `.md-ask-result`, `.md-ask-clear`) → `bridge.askStart(AskRequest)` → IPC `ask:start` → `app/src/askClaude.ts` spawns `claude` (found by `findClaude` in `setup.ts`, env `claudeEnv()`: login-shell PATH) in `<userData>/ask-claude` with `claudeArgs` and the prompt on **stdin** (several claude options are variadic and would swallow a positional prompt; every option is written `--opt=value`). stdout stream-json → `parseStreamLine` → `ask:event` (`AskEvent`) → `web/src/askRun.ts` (module store outside React: a run outlives the box; `onAskFinished` → App toast when the box is closed).
- **MCP config** (`mcpConfigFor`): server `mydraw` = `process.execPath` (the app's own binary) with `ELECTRON_RUN_AS_NODE=1` on `Resources/mcp/index.js` (packaged) or `<checkout>/mcp/dist/index.js`, `MYDRAW_USER_DATA` = this app's userData, `MYDRAW_NO_LAUNCH=1`. Independent of the user's `claude mcp` registration (`--strict-mcp-config`).
- **Follow-ups / outline** (`AskRequest.resume`, `.plan`): sessions are kept (Claude Code's own store, under `<userData>/ask-claude`); `parseStreamLine` reads `session_id` from init/result; `askRun.ts` keeps `sessionId`, `drawingId`, `thread` (earlier turns, `.md-ask-thread`); an Ask after a finished run on the same drawing sends `--resume=<id>` (`followUpSession`). **New conversation** (`.md-ask-clear.md-ask-new`) forgets it. "Outline first" (`.md-ask-plan`, `localStorage mydraw.askPlan`): system prompt PLAN FIRST (no changes), then **Build it** (`.md-ask-build`) resumes with "Build it as outlined.". `askSystemPrompt` adds the matching domain guides (`conventionsFor`, `shared/conventions.ts`: aws, azure, gcp, kubernetes, network, flow; at most 2) or points to `get_conventions`.
- **Limits**: `--tools=` (no built-in tools), `--allowedTools=mcp__mydraw`, `ASK_DISALLOWED_TOOLS` (library/theme/preset deletes, add_stencil_file); system prompt (`askSystemPrompt`) names the drawing (tab id, passed as `drawing` on every call), the selection, no save/export unless asked, short plain answer. One run at a time; Cancel = SIGTERM to the process group (`detached: true`, kills the MCP child too); 15 min cap; killed on quit. User settings/hooks of Claude Code still apply (it is their Claude Code).
- **Design guide** `DESIGN_GUIDE` (`shared/recipes.ts`): colour by role (same hues as `shared/nodeRoles.ts`), stroke widths, fills, shadows, arrow kinds/weights, zone kinds, grid, real topology, compact legend, steps/views, and a 6-point self-check (clipped text, legend size, zone colours, looping arrows, labels on long arrows, empty space) with screenshot + lint. Appended to every Ask's system prompt; inside `POLISH_RECIPE`; summarised in the MCP `instructions`.
- **Polish with Claude**: mode `polish` = `POLISH_RECIPE` (restyle only: update_elements / copy_look / add_legend; never moves, renames, deletes or re-routes); MCP prompt `polish_diagram {drawing?, focus?}`; `MenuCommand` `polishWithClaude`.
- **Tidy with Claude**: `askPrompt` mode `tidy` = `TIDY_RECIPE` (`shared/recipes.ts`, also the MCP `tidy_diagram` prompt) with the box text as focus; a selection forces keep-arrangement. `MenuCommand` `askClaude` (toggle box, ⌥⌘J in App's capture keydown) / `tidyWithClaude` (opens the box and starts).
- **Model**: `Settings.askClaude.model` sonnet|opus|haiku (aliases `claude --model` takes), box select + Preferences `SegmentRow`.
- **Tests**: `tests/askClaude.test.ts`; smoke "Ask Claude box" with a fake `claude` (`MYDRAW_CLAUDE`, written into the smoke work dir) that reads `--mcp-config`, starts that MCP server, calls `add_elements` on the drawing named in `--append-system-prompt` and prints stream-json; a prompt with `SLOW` waits (Cancel test).

## Diagram generation (Phase 5)
- `shared/diagram.ts`: `DiagramSpec` (nodes, edges, zones, direction, algorithm, routing, legend), `normalizeSpec` (validates agent input, fills edge ids), zone palette/tints, `uniquifySpec` (renames ids that clash with the drawing; used for Mermaid and templates).
- `shared/layout.ts`: ELK via `elkjs/lib/elk.bundled.js` (no worker). Zones are compound nodes (`INCLUDE_CHILDREN`), coordinates absolute (`elk.json.shapeCoords/edgeCoords: ROOT`). ELK can ignore a compound's minimum size with cross-hierarchy edges, so zones are widened afterwards.
- `shared/routing.ts`: `elbowRoute` (simple orthogonal router used by `connect`/reroute), `tidyRoute` + `inset` (clean ELK routes: drop collinear points, give end runs room, stop 5px short), `curvedPoints`, `fixedPointFor`.
- `shared/mermaid.ts`: own flowchart parser -> DiagramSpec (same layout/zones as build_diagram). Non-flowchart Mermaid goes through `@excalidraw/mermaid-to-excalidraw` (dynamic import, renderer).
- **Fonts before measuring**: registered fonts load lazily, and text measured before its font loaded got a box too narrow for the real font (titles/zone titles/legend labels clipped). `ensureFontsLoaded(ids)` / `ensureFontNamesLoaded` (`web/src/fontRegistry.tsx`, `FontFace.load()` on Excalidraw's registered faces) run at the start of every executor command for every look's fonts (`lookFontNames`), `fontFamily` values in the params and the drawing's current font.
- **Zone kinds** `shared/zoneKinds.ts` (pure, `tests/zoneKinds.test.ts`): `DiagramZone.kind` cloud|region|az|vpc|subnet-public|subnet-private|security-group|autoscaling|cluster|namespace|network|dmz|onprem|trust|tier|group -> `ZONE_KIND_STYLES` (AWS guideline colours, az/region dashed outlines). `zoneColors` = given colour, else kind (given or `inferZoneKind(label)`), else `neutralZoneStyle(depth)` (no more palette colours in turn). Stored as `customData.mydrawZoneKind`, shown by `get_scene` (`kind`); `create_zone {kind}` too. Lint allows these colours.
- **Grid** `shared/gridLayout.ts` (pure, `tests/gridLayout.test.ts`): `DiagramSpec.grid {id, label?, parent?, rows, columns, cells?}` + node `cell: "row/col" | "row/*"`. `normalizeSpec` adds zones (outer if labelled, `<id>.<col>` kind az, `<id>.<row>.<col>` kind from the row label) marked `grid`, sets node zones, and is idempotent (main and renderer both normalize). `layoutGrid` lines up rows/columns. Spanning: `row/*` or `*/col`; with an even count of columns (rows) the node sits in the widened gap between the two middle ones (ALB between two AZs), otherwise in a strip above the row (at the top of the column); a column-spanning node's zone is the column band. `buildDiagram` (`planGrid`) gives ELK one placeholder node `<id>::grid`, proxies edges to it, then `expand`s and routes arrows touching the grid with `routeEdges` (best of 4x4 sides through `routeAround`, ports along a side taken in turn from `SLOTS` so arrows fan out, zone title strips as walls), then `separateParallel` slides shared runs apart.
- **Stored spec / rebuild**: every element `buildDiagram` adds carries `customData.mydrawDiagram` (id `dgm-…`, also on view frames), the first one `mydrawDiagramSpec` (`storableSpec`: no grid zones, no x/y). `diagramsIn(scene)`; MCP `get_diagram_spec {diagram?}`; `build_diagram {replace: id | true}` rebuilds at the old top-left keeping the id (`commitReplace` in the executor: at the old diagram's stacking position, reused ids version-bumped, the rest deleted, one undo step). The recipes and design guide tell Claude to change built diagrams by spec. Tidy/Polish runs may not call `raw_update` / `set_scene` (`ASK_RECIPE_DISALLOWED_TOOLS`). `auto_layout` refuses a drawing with grid zones (`customData.mydrawGrid`) unless `force`.
- **Steps / views / showData**: edge `step` -> `stepBadge` (ellipse + number, `customData.mydrawStep`, `mydrawStepOf`) 28 px along the arrow; `steps: string[]` -> badge + text rows under the diagram (`mydrawSteps`). `views: [{name, kinds?, weights?, steps?, nodes?}]` -> `framedViews`: the diagram in a frame, then a `cloneForInsert` copy per view below it (customData ids remapped), elements outside the view at opacity 18; result `pages`. `showData: [keys]` fills empty node subtitles from `data` (in `normalizeSpec`). Badges are not bound to arrows; `shared/stepBadges.ts` `badgeFixes` puts them back (28 px along the arrow; deleted with it) in the executor's `commit()` (`keepBadgesOnArrows`) and on user edits (`followBadges` in `web/src/zoneFollow.ts`, EVENTUALLY). Lint and the quality measure skip badges and the steps list.
- **Legend** `buildLegend({icons: auto|all|none})` (`add_legend icons`, `build_diagram legendIcons`): auto drops rows for captioned icons without a kind (fallback: icons when nothing else); role rows skip plain icon nodes (their colours are the icon's); more than `LEGEND_ROWS_PER_COLUMN` (8) rows -> two columns. Lint rules `zone-colors` (> 4 zone colours without kinds) and `legend-too-big` (> 10 rows), info.
- `shared/templates.ts`: starter specs. Icons are names or `Collection:query` (`findStencil` in `shared/library.ts`); missing packs fall back to shapes with a warning.
- `web/src/agent/diagram.ts`: `makeIconNode`, `makeZone`, `buildDiagram`, `buildLegend`, `autoLayout`. Main (`app/src/agent.ts`) validates specs and resolves icons, the renderer builds and commits (one undo step).
- **Icon node** = borderless container rectangle (caption = bound text, `verticalAlign: bottom`) + image, grouped; `customData.mydrawNode = "icon"`, `mydrawStencil`. Arrows bind to the container so they never cross the caption; `bindTarget` redirects an image/caption id to its node. `recolor`/`get_color` on a node act on its image. `get_scene` shows it as `type: "icon-node"` and hides the image. A node placed across a zone/frame border gets a fill in the canvas color (`mask`).
- **Zone** = locked tinted rectangle (`customData.mydrawZone`) + title text (`mydrawZoneTitle`), grouped. Membership (also of nested zones) is `customData.mydrawZoneId`; `withGroupsAndLabels` brings a zone's contents, so `move` carries them. Deleting a zone keeps the contents (they move up to the parent zone). Zones go behind their members (`commit(..., beforeId)` inserts with `index: null`). Moving a zone rectangle (hand-drag after unlocking, arrow keys, `update_elements`) carries its contents: `web/src/zoneFollow.ts` compares each `onChange` with the previous positions and translates contents that did not move (`EVENTUALLY`, so it merges into the same undo step). Zones are locked by default. **Editing by hand** (`shared/zoneEdit.ts` pure + `tests/zoneEdit.test.ts`; `web/src/zoneEdit.ts`): App's capture pointerdown on the canvas: a click on a locked zone title (`zoneTitleAt`, topmost) unlocks the zone + title (`customData.mydrawZoneUnlocked`, NEVER), selects the rectangle inside its group (`editingGroupId`, so a resize doesn't scale the title) and swallows the click; `relockZones` in App's onChange locks it again once neither is selected nor being edited (`zonesToRelock`; skipped while `cursorButton === "down"`, Excalidraw clears the selection mid-press). Hover cursor class `md-zone-title-hover`. `followZones` keeps the title at the top-left when a zone is resized. Smoke: "Zones by hand".
- **Elbow arrows**: Excalidraw re-routes `elbowed` arrows itself when the user drags a bound shape, but only with `fixedPoint` bindings (ratio of the bound box, 5px outside, `gap: 0`). `restoreElements` (raw_update/set_scene of new arrows) drops such bindings, so build them with `connectorElements`. Agent moves re-route with our own `elbowRoute`. Lines can't be Excalidraw elbow arrows: an elbow line is a plain line with `customData.mydrawRouting`. Curved = round arrow with 3 points (`mydrawRouting: "curved"`).
- Excalidraw puts an arrow label at the middle point (odd count) or the middle of the middle segment (`labelPoint`); `convertToExcalidrawElements` shifts multi-point arrows, so `connectorElements` re-applies the route.
- `auto_layout` moves an existing legend to the bottom-right below the new layout (whole-drawing runs only). `layoutGraph` runs `avoidTitleStrips` on orthogonal routes: a run through a zone title is nudged past it, or jogged around it when an end point is pinned to its node.
- Legend rows: icon nodes (kind or stencil name), and shapes/arrows with `customData.mydrawKind` (`kind` in build_diagram). Legend elements carry `mydrawLegend`; `add_legend` replaces old ones.

## Diagram quality (clean arrows and labels)
- **Measure** `shared/diagramQuality.ts` (pure, `tests/diagramQuality.test.ts`): `measureQuality({nodes, zones, routes})` -> `{metrics, issues, score, advice}`: arrows on top of each other (parallel runs closer than `TRACK_MIN` 9 px sharing > 12 px, ignoring the first/last 20 px where arrows fan out of a node), arrows through nodes they don't connect (`nodesThrough`; nodes inside a zone the arrow ends at are fine), labels under nodes / zone titles / other labels / other arrows, crossings, arrows cutting through zones that hold neither end (`zonesCrossed`, weight 15), bends, length, aspect (penalised only from 8 nodes). Weights in `QUALITY_WEIGHTS`; lower score is better.
- **Tidy** `shared/edgeTidy.ts` (`tests/edgeTidy.test.ts`): `separateParallel` slides interior runs (and end runs along their node's side) 14 px apart when that lowers the local cost; `placeLabels` puts each label on a free stretch of its own route (candidates at 20-80% of segments long enough; collisions cost most, a vertical stretch costs 25 because the arrow would run through the text); `tidyRoutes` = both.
- `separateParallel` stops after `MAX_ATTEMPTS` (3000) shifts; `placeLabels` avoids labels lying across a zone outline; when tidying would push a run into a node, `drawnRoute` keeps the plain ELK route (whose end run may then be short under the arrowhead).
- **Pipeline** `shared/layoutPipeline.ts`: `drawnRoute` (tidyRoute + inset; falls back to the plain ELK route when tidying would push a run into a node: ELK's own routes never hit nodes), `routesOf`, `tidiedRoutes`, `qualityOfLayout`. **Variants** `shared/layoutBest.ts`: `layoutBest(input)` runs `layoutGraph` with up to 6 option sets (`VARIANTS`: base, free-order, balanced, roomy, linear, other-direction (only when direction is open)), scores each on the routes that will be drawn and keeps the lowest; <= 12 nodes try 2, stops early when clean, ~4 s budget, deterministic. `LayoutInput.elkOptions` carries a variant's ELK options. Fixtures `tests/fixtures/diagrams.ts` (homelab, aws) and `tests/layoutQuality.test.ts` pin the result (recorded: homelab 1257 -> 447, aws 3286 -> 958; labels colliding 6/10 -> 0/1, arrows on top of each other 11/36 -> 2/0).
- **Used by** `buildDiagram` and `autoLayout` (`web/src/agent/diagram.ts`): they draw `best.routes` (translated with `translateRoutes`) and pass each label's centre to `connectorElements(..., labelAt)`, which uses it when it lies on the route. Both return `quality: qualitySummary(best)` (score, layout, arrowsOnTopOfEachOther, arrowsThroughNodes, labelsColliding, crossings, aspect, advice).
- **Lint** `shared/lintQuality.ts` adds rules `edge-overlap`, `label-collision`, `edge-through-node` (warnings) and `crowded-node` (7+ arrows), `long-edge` (> 60% of a diagram at least 800 px) (info), computed from element JSON (`qualityInputOf`); fixes `{kind:"label"}` (move the label to the free stretch `placeLabels` picks) and `{kind:"reroute"}` (`rerouteAround`), applied by `fixChanges` in `web/src/lintOps.ts`. The 60 px label guard in `commit()` still holds: a label placed on a stretch of its own arrow is never detached.
- **Guidance** for the agent lives in the MCP `instructions` and the `build_diagram` / `auto_layout` / `lint_diagram` descriptions (about 40 arrows at most; one arrow to a zone instead of many to its nodes; labels only on short arrows; read `quality.advice`; lint and screenshot before saying done; save the drawing).

## Diagram looks, shapes and arrow semantics
- **Looks** `shared/diagramLook.ts` (pure, `tests/diagramLook.test.ts`): `look: "polished"` (DEFAULT since 0.2: professional type + `roleColors` (each node's fill = `ROLE_STYLES[role].fill` (hue-50), stroke = hue-700, unless the node gives `color`/`fill`; icon nodes keep their colours and ink captions; external = dashed), strokes 2 / primary 3, edges primary 3.5, `nodeShadow` soft / `primaryShadow` lifted unless the spec or node sets `shadow` (null = none); `customData.mydrawRole`; `buildLegend` adds one row per role when 2+ roles and the shapes have no `kind`). Roles: `shared/nodeRoles.ts` (`NODE_ROLES`, `ROLE_STYLES`, `inferRole`: explicit `role`, else shape (cylinder data, queue, actor entry, cloud external, server compute, folder/document storage), else keyword rules over kind/icon name/label, default service; `tests/nodeRoles.test.ts`). `"professional"` (plain: white nodes, no shadows; roughness 0, Montserrat Bold title, Inter SemiBold zone titles and labels, Inter Bold for primary nodes, Inter captions/arrow labels, IBM Plex Mono subtitles) or `"sketch"` (roughness 1, Permanent Marker, Kalam, Caveat). Fonts are names resolved by `fontIdByName` with an Excalidraw fallback. The drawing's Clean/Sketch setting no longer styles generated diagrams; Claude passes `look: "sketch"` when the user asks for hand-drawn. Measuring (node sizes, zone titles via `zoneTitleSize(label, font, size)`, label sizes for layout) uses the look's fonts.
- **Arrow semantics**: edge `weight` primary/normal/secondary (3 / 2 / 1.25 px; secondary at 70% opacity), `head`/`tail` (any Excalidraw 0.18 arrowhead incl. crowfoot_*, or none; `arrow` end/both/none still works), `kind` + spec `kinds: {kind: {color, style, weight, head, tail}}`; `edgeLook` merges edge > kind > look (null arrowheads are values, not "missing"). `kindStyles` gives undeclared kinds distinct, stable colours from `KIND_PALETTE`. The legend samples show each kind's width, dash and head; it drops icon rows when there are more than 10 icon types.
- **Drawn shapes** `shared/shapeSvgs.ts` (pure, `tests/shapeSvgs.test.ts`): `cylinder, cloud, document, queue, actor, server, hexagon, folder` as SVG outlines (stroke inset by half its width, colours sanitised, recolourable). `buildDiagram` draws them with `shapeImage` (SHA-1 file id, truecolor SVG) inside an icon-node container (`customData.mydrawNode = "icon"` + `mydrawShape`), label inside (`makeIconNode({labelInside: true})`, verticalAlign middle) or under it for actor/server (`CAPTION_SHAPES`). **Order matters**: the image is pushed BEFORE the container, because Excalidraw draws a bound label right after its container and the filled image would cover it. `get_scene` shows `type: "shape-node"`, `shape`. Default fill white (stays white in dark mode, like icons).
- **Emphasis / subtitles**: node `emphasis` primary (border `look.nodeStroke.primary`, bold label) / muted (grey `look.muted`, faded); node `subtitle` = a grey mono text element (`customData.mydrawSubtitleOf`), grouped with the node, inside shapes (node grows) or under an icon's caption (layout box includes it; the container does not). Stored as `customData.mydrawSubtitle`, shown by `get_scene`. A hand resize does not re-centre it.
- **Polish**: equal widths per (zone, node type) before layout (shapes also equal heights); diagram `subtitle` under the title; zone outlines `look.zoneStroke` outer/inner; `auto_layout` measures zone titles from the drawn title text.

## Layout grid and the static canvas hook
- **Excalidraw internals**: the grid and the dark theme hook Excalidraw's renderer. Every assumption is listed in the header of `web/src/canvasHook.ts` and in `EXCALIDRAW-UPGRADE.md`; re-check them on any Excalidraw upgrade.
- `shared/grid.ts` (pure, `tests/grid.test.ts`): `GridSettings` (enabled, size 4..100, majorEvery, style lines|dots, color, opacity, snap), `normalizeGrid` (untrusted input; patches merge onto the current grid in `mergeSettings`), `planGrid` (lines for a view; thinned below 8 screen px, majors kept), `snapOffset`, `excalidrawGridState`, `FILE_GRID_STATE`, `preDarkColor`/`applyDarkFilter` (model of Excalidraw's dark filter `invert(93%) hue-rotate(180deg)`; saturated warm colours are only approximately reachable). Global setting `Settings.grid`, not per drawing.
- **Static canvas hook** (`web/src/canvasHook.ts`, `CanvasHook`): wraps the static canvas's 2D context (instance methods `fillRect`, `restore`, path/stroke calls). The full-canvas background `fillRect` that starts each render begins a render: it decides the dark mode for it, paints the grid (`paintGrid`, `web/src/gridPaint.ts`) between background and shapes, and arms the filter to re-apply after the `restore()` that closes the background fill (armed only after the grid painter's own save/restore).
- **Dark theme in-canvas**: in dark mode the hook sets `canvas.style.filter = "none"` (overriding Excalidraw's CSS `--theme-filter`) and `ctx.filter = THEME_FILTER` for the background and every element, like Excalidraw's dark exports; the grid is painted unfiltered (exact colour). `web/src/darkImages.ts` patches `CanvasRenderingContext2D.prototype` once: setting `IMAGE_INVERT_FILTER` on a detached canvas (an image's element canvas) sets `none` instead and remembers the canvas; drawing such a canvas onto a context marked by `setInCanvasTheme` uses no filter (exact colours), anywhere else `IMAGE_INVERT_FILTER` (what Excalidraw would have drawn). An element drawn on a themed render while `ctx.filter` is not `THEME_FILTER` reports `themeLost`. Light mode and the fallback use Excalidraw's own CSS filter; with the CSS filter the grid colour goes through `preDarkColor`. While grid mode is on, single-segment strokes in `#dddddd`/`#e5e5e5` (Excalidraw's `strokeGrid`) are skipped. Exports render on other canvases, so they never contain the grid.
- **Live snapping** = Excalidraw's own grid mode (`gridModeEnabled` + `gridSize`), its lines hidden by the hook. `web/src/useCanvasHook.ts` (per `DrawingView`) applies the state with `CaptureUpdateAction.NEVER`, forces repaints by flipping `gridStep` 2/3 (a static-canvas prop), and treats a `gridModeEnabled` change it did not make (Excalidraw's context-menu "Toggle grid") as toggling our grid. Snapping only while the grid is visible; ⌘ held while dragging bypasses it (Excalidraw). ⌘' is caught in App's capture keydown so Excalidraw's own ⌘' never runs. `serializeScene` writes `FILE_GRID_STATE`, so files never carry the app's grid.
- **Health check / fallback**: after each grid or theme change on the visible tab (grid on or dark mode), `useCanvasHook` forces a render and compares `CanvasHook.settle()` counters: no render seen (twice) → `mode: "overlay"` (`web/src/GridOverlay.tsx`, a canvas above the drawing, no live snapping, Excalidraw's CSS dark filter); grid-mode renders with nothing suppressed → `snapOk: false` (grid mode stays off); `themeLost` → `themeOk: false` (CSS dark filter). The panel shows a warning, a `console.warn` names `EXCALIDRAW-UPGRADE.md`. `window.__mydrawNoGridHook = true` simulates a broken hook (smoke uses it). Test hook: `__mydrawTest.canvasStatus()`, `__mydrawTest.darkImageStats()`, `__mydrawTest.api()`.
- `web/src/GridPanel.tsx`: floating non-modal controls (live preview), open state in `localStorage mydraw.gridPanel`. Commands `toggleGrid`, `gridSettings`, `snapToGrid` (`web/src/gridOps.ts`: snaps each unit's top-left via `applyUpdates`, one undo step).

## Routing around shapes (⌘-link, route_around)
- **Router**: `shared/avoidRoute.ts` (pure, `tests/avoidRoute.test.ts`). `routeAround({start, startSide, end, endSide?, startBox, endBox, obstacles, waypoints, clearance 16, stub 20, bendCost 40})`: A* over a sparse orthogonal grid made of the inflated obstacles' edges (+ the leg's end points), state = (node, direction), cost = length + bend penalty, no U-turns, leaves straight out of `startSide` (stub) and arrives at the stub in front of `endSide` from any direction but straight back. Facing sides: lined-up ports with nothing between = one straight segment; a short gap shrinks the stubs to half of it (otherwise the stubs overshoot each other and the route doubles back). Legs between waypoints; obstacles limited to a 400px region around each leg. Clearance falls back 16 → 8 → 2; if still blocked a plain elbow with `ok: false`. `compress` keeps reversal corners (dedupe in routing.ts would drop them). Helpers: `portPoint`, `nearestSide`, `snapRatio` (quarter points), `fixedSegmentsFor`, `crossesBox`, `alignedPorts` (facing sides that overlap across get both ports on one line, so the link is straight; with an aimed spot only when it lies in the overlap; not with bend points or curved links).
- **Durable arrows**: an around-arrow is a native elbow arrow (`aroundFields` in sceneOps: fixedPoint bindings, `elbowed`, `roundness: null`, `startIsSpecial/endIsSpecial: false`) whose middle segments (index 2..n-2) are Excalidraw `fixedSegments`: when a bound shape is dragged Excalidraw only redraws the end runs (`handleEndpointDrag`), so the route survives, the user can still drag segments, and save/load keeps it (restore doesn't re-route). Routes with < 4 points have no fixed segments (Excalidraw re-routes them freely). `customData.mydrawAvoid = true` marks them: `reroute()` (agent moves, `applyUpdates`) re-routes them with `rerouteAround` (sides/positions kept via `nearestSide` of the old endpoints); other elbow arrows get `fixedSegments: null` on re-route (stale segments would not match). `routingFields` (explicit routing style) drops `mydrawAvoid`.
- **Obstacles** (`avoidObstacles` in sceneOps): every element's drawn box except arrows/lines/freehand/frames, text inside shapes, the excluded ids (arrow, ends, unit members), things inside an end box (an icon's image/caption) and things drawn around an end (zones/boxes it sits in).
- **Link mode** (`web/src/LinkMode.tsx` + `web/src/linkOps.ts`): `LinkPlanner(api, sourceUnitId, side)` snapshots the scene and plans previews (`plan(end, waypoints, routing, unitOf)`; `end` = `{unitId, side|"auto", ratio}` or `{point}`; "auto" tries all 4 sides and keeps the cheapest). `createLink` builds the arrow via `buildElements` (current style, boundElements) and overrides geometry; one undo step; selection untouched. Window capture listeners (the overlay has `pointer-events: none`, so wheel/zoom keep working): pointerdown on a target = connect (Shift = keep going), on empty canvas = bend point, a second empty click within 450ms/8px = free end (pointer events carry no click count; the following `dblclick` is swallowed or Excalidraw would start a text), off-canvas = end link mode, right-click/Esc = cancel; pointerup after a drag from the handle onto a target = connect. Keys (swallowed so Excalidraw tools don't switch): R routing (around/elbow/straight/curved), A heads (end/both/none), D dashed (persisted in `localStorage mydraw.linkStyle`), Backspace removes the last bend, Enter ends at the pointer. Pointing within `SIDE_BAND` (22 screen px) of a target side picks that side and the nearest quarter point; over the middle the best side is picked. Body class `md-linking` = crosshair cursor. Smoke selectors: `.md-qc-linkmode`, `.md-qc-path`, `.md-qc-target`, `.md-qc-port`, `.md-qc-wp`, `.md-qc-link-keys`.
- **MCP align / distribute**: `shared/arrange.ts` (pure, `tests/arrange.test.ts`: `alignMoves(units, edge, ref?)`, `distributeMoves(units, axis, gap?)`); executor cases `align` / `distribute` build one unit per id with `withGroupsAndLabels` (ids of the same unit count once; `to` = reference that stays put), move through `applyUpdates` (arrows re-route), one commit. The app's own Align section is Excalidraw's (see Align & distribute).
- **Tidy and Re-layout** (`web/src/tidyLayout.ts`; `MenuCommand` `tidyLayout` = Tidy, `relayout`; menu Diagram + palette; selection or whole drawing; one undo step). Both start from `collectUnits` in `web/src/agent/diagram.ts` (units = shapes / icon nodes / groups; a free text within `NOTE_DISTANCE` 30 px of a unit travels with it; zones; arrows between units). **Tidy** = `tidyDrawing` + pure `shared/tidy.ts` `tidyLayout` (`tests/tidy.test.ts`): per container, inner zones first: line up near-rows/columns on their median (zones excluded), even nearly even gaps (spread ≤ 2.5×, not when it would break a column/row), push overlaps apart (`minGap` 24), grow zones (never shrink); applied only if `currentScore` (layout quality score + `nodeOverlaps` × `OVERLAP_WEIGHT`) does not get worse, overlap fixes always. **Re-layout** = `autoLayout` with `onlyIfBetter` (kept only when it beats the current score by 5 % / 5 points): direction from `inferDirection` (arrows' net flow, else layoutBest tries both), nodes fed to ELK in `byReadingOrder` (ELK keeps input order, so the result resembles the drawing), all `VARIANTS` tried, and with ids `makeRoom` pushes neighbours out of a grown selection. MCP: `tidy {ids?}`, `auto_layout {onlyIfBetter, makeRoom}`; prompt `tidy_diagram {drawing?, focus?, keep?}` (`TIDY_RECIPE` in `shared/recipes.ts`: scene + screenshot, roles, tidy / auto_layout / align / distribute / route_around, lint + screenshot, report; reused by the Phase 10 button). Smoke: "Re-layout", "Tidy".
- **Elsewhere**: palette "Route arrows around shapes" (`routeArrowsAround`: selected arrows, else all; one undo step); MCP `connect {avoid: true}` and `route_around {ids?}`.

## How to drive mydraw (for Claude)
0. A whole diagram: `build_diagram` (or `mermaid_to_scene`, `apply_template`); then refine with the steps below and `auto_layout` to tidy.
1. `list_drawings` / `new_drawing` / `open_drawing`; `get_scene` for ids.
2. Shapes with labels in one `add_elements` call (give your own ids like `"web1"` so you can refer to them); arrows as `{type:"arrow", from, to, label}` in the same call or via `connect`.
3. Icons: `search_stencils "ec2"` → `place_stencil {id, right_of: "web1", label: "web-1"}`; connect to the returned `node` id. Zones: `create_zone {label, ids}`. Connectors: `routing: "elbow" | "curved"`.
4. `screenshot` to check the layout; fix with `tidy` / `move` / `align` / `distribute` / `update_elements`; `zoom_to_fit` so the user sees it.
5. `save {path}` and `export {path: ".../x.png"}`; other formats by extension (`.webp .svg .html .pdf .pptx .drawio .mmd .csv .md`), `scope: "frame"`/`"frames"` for frames (pdf/pptx/drawio: one file, a page/slide per frame), `get_scene` first to see frame names. PDF: `pageSize` fit/a4/letter, `actualSize`; PPTX: `slideSize`.
6. Without the app: `mydraw export x.excalidraw --format pdf --scope frames`, `mydraw convert x.drawio --to excalidraw`.
7. Text to diagram: `import_diagram {format: csv|yaml|mermaid, text | path}` (CSV host list or from/to list, YAML spec with `a -> b: label` edges, Mermaid). Properties: `set_properties {id, properties}`; review: `get_inventory`. Arrows: `connect {from, to, avoid: true}` routes around shapes; `route_around {ids?}` re-routes existing ones; `lint_diagram {fix: true}` applies the safe fixes.
8. Fonts: `list_fonts`, then `fontFamily: "Caveat"` (fun) or `"Inter Bold"` (professional) on text, labels or `update_elements`.
9. Effects: `fillStyle` (`dots`, `dashed`, `zigzag`, `zigzag-line`, plus Excalidraw's), `gradient` (`"sky"` or `{from, to, kind, angle}`; rectangles/diamonds/ellipses), `strokeStyle` dash names (`dash-dot`, `long-dash`, ...), `shadow` (`"soft"`, `"inner"`, `"neon"`, `"extrude"`, `"float"` or `{kind, ...}`), `textOutline`. Accepted by `add_elements`, `update_elements`, `build_diagram` (node `gradient` / `fillStyle` / `strokeStyle`, edge and zone `style`, diagram `shadow`) and style presets (`apply_style_preset {style: {gradient, shadow, strokeStyle}}`; built-ins "Sky gradient", "Sunset gradient", "Flat fill").

## Conventions
- **Excalidraw upgrades**: follow `EXCALIDRAW-UPGRADE.md` (procedure + every internal mydraw relies on, with where it lives in Excalidraw and how it is tested). When you add code that depends on Excalidraw internals (DOM classes, test ids, renderer behaviour, undocumented API quirks), add a row there.
- Excalidraw is pinned to `0.18.1`. Import types from `@excalidraw/excalidraw/types` and `@excalidraw/excalidraw/element/types`.
- `process.env.IS_PREACT` must stay defined as `"false"` in `vite.config.ts`.
- Fonts are copied from the package into `web/public/fonts` by `scripts/build-app.mjs` (gitignored).
- Edit menu: undo/redo/select-all use `registerAccelerator: false` so the keys reach Excalidraw.
- No browser `alert/confirm`; use the main-process dialogs (`askUnsaved`) or in-app banners/toasts.

## Checks before committing
`npm run typecheck && npm test && npm run smoke` (`npm run build` also builds the MCP server); packaging changes also `npm run package && npm run verify-package`

The smoke test runs the built app with `MYDRAW_TEST=1`, a temp `MYDRAW_USER_DATA` and a temp `MYDRAW_LIBRARY`, and uses the test-only `window.__mydrawTest` hook (`web/src/App.tsx`). Extend it when adding features.
